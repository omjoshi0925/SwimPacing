# Data dictionary

Tasks 7 and 8. Schema for the 200 yard freestyle SCY dataset.

**Scope of the first dataset.** Male swimmers, ages 15-18, 200 freestyle, short
course yards, individual event swims from sanctioned competition. Do not mix
courses, strokes or distances into this file. Homogeneity is what makes 50 races
informative instead of noisy.

---

## Raw file: `data/raw/200_free_scy_raw.csv`

One row per race. Times in `m:ss.hh` or plain seconds; the pipeline parses both.
Cumulative splits, exactly as a split sheet reports them.

| Column | Type | Required | Description |
|---|---|---|---|
| `swimmer_id` | string | yes | Anonymized, `S001`, `S002`, … Never a real name. |
| `meet_id` | string | yes | Short stable code, e.g. `2026_SEC_CHAMPS`. |
| `meet_name` | string | yes | Meet name as published. |
| `meet_date` | date | yes | `YYYY-MM-DD`, the date of **this swim**. |
| `age` | int | yes | Age at the meet, 15-18 for this dataset. |
| `sex_category` | string | yes | Competition category as entered, `M` here. |
| `event` | string | yes | `200 FR`. |
| `course` | string | yes | `SCY`. |
| `round` | string | yes | `prelim`, `final`, `swimoff`, `timed_final`. |
| `seed_time` | time | no | Entry time for this meet. |
| `pre_race_pb` | time | yes* | Best time **before this race**. See the rule below. |
| `final_time` | time | yes | Official final time. |
| `split_50` | time | yes | **Cumulative** time at 50. |
| `split_100` | time | yes | **Cumulative** time at 100. |
| `split_150` | time | yes | **Cumulative** time at 150. |
| `split_200` | time | yes | **Cumulative** time at 200; should equal `final_time`. |
| `data_source` | string | yes | Where this row came from, precisely enough to re-find it. |

`yes*` — `pre_race_pb` is required for the H1 analysis. Rows without it are kept
for shape analysis and excluded from the performance regression.

### Optional columns, in order of value

| Column | Type | Why it matters |
|---|---|---|
| `split_15m` | time | **The single most valuable optional column.** It is the only way to measure the dive-start credit rather than assume it, and that credit is the weakest number in the model. Record it whenever available. |
| `reaction_time` | float | Block reaction, seconds. |
| `splits_25` | string | Eight 25 splits, semicolon-separated. Enables the Task 19 eight-segment model. |
| `turn_times` | string | Per-turn times if published. |
| `underwater_distances` | string | Breakout distances if published. |
| `meet_level` | string | `dual`, `invitational`, `sectional`, `state`, `national`. |
| `lane` | int | |
| `team` | string | Team code only, never an identifying roster. |
| `prelim_time` | time | For finals rows, the same swimmer's prelim. |
| `finals_time` | time | For prelim rows, the same swimmer's final. |
| `stroke_rate` | float | Cycles/min if published. |
| `stroke_count` | string | Per-length stroke counts, semicolon-separated. |
| `notes` | string | Anything unusual: suit, altitude, timing malfunction. |

## The `pre_race_pb` rule

**`pre_race_pb` must be the swimmer's best 200 SCY freestyle achieved strictly
before the date of this race.**

Do not use a career best, a season best that includes later swims, or whatever
number a results site currently displays as their PB. Those all leak the outcome
into the predictor and will manufacture a spurious relationship in the H1
analysis.

If a swimmer has never swum the event before, leave `pre_race_pb` blank rather
than substituting a seed time. Blank is honest; a guess is not.

Practical method: sort that swimmer's race history by date and take the minimum
of all times strictly earlier than this meet date. `src/preprocessing.py`
provides `derive_pre_race_pb()` to do this from the raw file, which is more
reliable than typing it by hand.

## Processed file: `data/processed/200_free_scy_processed.csv`

Generated by `src/preprocessing.py`. Never hand-edited. Carries every raw column
plus:

### Derived split times

| Column | Definition |
|---|---|
| `split1_time` | `split_50` |
| `split2_time` | `split_100 - split_50` |
| `split3_time` | `split_150 - split_100` |
| `split4_time` | `split_200 - split_150` |

### Normalized pacing (Task 10)

| Column | Definition |
|---|---|
| `P1`…`P4` | `split_i / final_time`; sums to 1 |
| `P1_corrected`…`P4_corrected` | free-swimming-equivalent shares: the dive credit is ADDED back to split 1 (`split1 + S`) and shares taken over the lengthened race, making them comparable with model raced fractions |
| `drop_1_2_corrected` | `drop_1_2 - S`: the lap-1-to-2 drop attributable to pacing rather than the dive; the fair M3-vs-M4 discriminator |
| `drop_ratio_corrected` | `drop_1_2_corrected / drop_3_4` |
| `first_half` | `split1_time + split2_time` |
| `second_half` | `split3_time + split4_time` |
| `half_difference` | `second_half - first_half`; positive means positive split |
| `closing_fade` | `split4_time - split2_time` |
| `split_variability` | standard deviation of the four splits |
| `max_split_difference` | `max - min` of the four splits |
| `pace_deviation_even` | RMSE of `P_i` against 0.25 |
| `drop_1_2` | `split2_time - split1_time` |
| `drop_3_4` | `split4_time - split3_time` |
| `drop_ratio` | `drop_1_2 / drop_3_4`; **the M3 versus M4 discriminator** |

### Performance

| Column | Definition |
|---|---|
| `performance_improvement` | `(pre_race_pb - final_time) / pre_race_pb`; positive means faster than previous best |

### Model deviations

| Column | Definition |
|---|---|
| `model_deviation_M0`…`M4` | RMSE of observed `P_i_corrected` against each model's predicted `P_i*` |
| `best_model` | model with the smallest deviation for this race |

### Quality flags

| Column | Meaning |
|---|---|
| `flag_missing_splits` | any cumulative split absent |
| `flag_non_monotonic` | cumulative splits not strictly increasing |
| `flag_time_mismatch` | `abs(split_200 - final_time) > 0.05` |
| `flag_implausible_split` | any 50 outside 0.5x-2.0x the race mean |
| `flag_duplicate` | same swimmer, meet, round appears more than once |
| `flag_course_mismatch` | `course` is not `SCY` |
| `flag_age_out_of_scope` | `age` outside 15-18 |
| `flag_no_pb` | `pre_race_pb` missing |
| `usable` | true when no blocking flag is set |

Only `usable` rows enter the analysis. Flag counts are reported, and per
`docs/validation_plan.md` §10, exclusions above 15% trigger a review of the
collection protocol rather than a quiet continuation.

## Collection protocol (Task 9)

**Target for the first pass: 50 complete races.** This is a pipeline test, not a
scientific sample. Per Task 9, no scientific claim comes out of these 50.

### Inclusion

1. 200 freestyle, SCY, individual event (not a relay lead-off; different start
   rules).
2. Male, age 15-18 at the meet.
3. All four cumulative splits published and plausible.
4. Sanctioned competition with official timing.

### Exclusion

- Relay lead-off legs.
- Disqualified swims.
- Time-trial or unofficial swims.
- Races where the split sheet is visibly broken (non-monotonic, mismatched
  final).

### Sampling

Prefer **several races per swimmer across a season** over one race each from 50
swimmers. Repeated measures give the mixed-effects model something to work with
and let you see whether a swimmer's pacing is stable. Record every swimmer's
races, not just their best ones: selecting on outcome would bias the H1 test
in exactly the direction that would appear to confirm it.

Spread across at least three meets, so meet-level effects such as pool, timing
system and taper are not confounded with swimmer.

### Anonymization

- Assign `S001`, `S002`, … in the order you first encounter each swimmer.
- Keep the name-to-ID mapping in a **separate local file that is never
  committed**, and only if you need it to look up later races.
- `.gitignore` already excludes `data/raw/*` and `data/processed/*`.
- Meet names and dates are fine; they are public and needed for reproducibility.
- Do not publish anything that reduces to a named minor's performance record,
  even though the source results are public. Aggregate and anonymized is the
  standard to hold to here.

### Recording

Type into `data/raw/200_free_scy_raw.csv` directly, or into a spreadsheet
exported to that exact header. Put a real, specific `data_source` in every row.
"SwimCloud" is not specific enough; a meet result URL or a named results PDF is.

Then run:

```bash
python -m src.preprocessing data/raw/200_free_scy_raw.csv
```

## Adding a meet: the multi-meet ingest protocol (Phase 8)

How every official Hy-Tek meet enters the dataset after the pilot. One meet is
one JSON config; the code never changes per meet.

1. **Retrieve the official section verbatim.** Open the meet's results page on
   the sanctioning body's own site (for Pacific Swimming, pacswim.org) in the
   browser, copy the full event section (header line through the last split
   line), and save it unmodified to `data/private/sources/<meet>_<event>.txt`.
   Official results only; aggregator pages (SwimCloud etc.) publish no splits
   and no ages and are recorded as separate sources when used at all.
2. **Record the checksum.**
   `python -m scripts.ingest_hytek --record data/private/sources/<file>.txt`
   prints the sha256. Verify the saved text against the live page at retrieval
   time (length plus spot checks at minimum; the pilot used a dual rolling
   checksum in the browser).
3. **Write the config** from `configs/meets/TEMPLATE.json`: meet identity,
   date, course, round, the exact source URL and retrieval date in
   `data_source`, the sha256, and the expected event header. The config is
   committed; the source file never is.
4. **Ingest:** `python -m scripts.ingest_hytek configs/meets/<meet>.json`.
   Refuses on checksum mismatch, event mismatch, or any parse problem.
   Re-running is idempotent (rows for that meet_id are replaced). The source's
   sha256 lands in the public integrity table in `data/DATASET_VERSIONS.md`.
5. **Reprocess:** `python -m src.preprocessing data/raw/200_free_scy_raw.csv`,
   then check the flag-count summary it prints before trusting new rows.

**Identity across meets.** Swimmers keep one S-number across meets and
sources; matching is on normalized (first, last) name tokens over every
recorded spelling variant. Known limitation: two different swimmers sharing a
normalized name would collide onto one ID. With ages present on official
results, an age discontinuity within one ID is the tell; check the private map
when a match looks suspicious, and record any manual resolution in the map's
name field rather than editing silently.
